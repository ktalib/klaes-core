Draft Autosave TypeError Fix Verification

🚨 Original Error

[2025-10-06 13:11:35] local.ERROR: array_keys(): Argument #1 ($array) must be of type array, string given
at C:\Users\Administrator\Documents\app\app\Http\Controllers\SubApplicationDraftController.php:91

Root Cause: Frontend was sending form_state as a JSON string, but backend was expecting an array and trying to call array_keys() on the string.

✅ Fix Applied

Solution: Updated SubApplicationDraftController::saveDraft() to handle both old and new autosave formats.

Backend Changes:

// Before (caused error)
Log::info('[SubApplicationDraftAutosave] saveDraft called', [
    'form_state_keys' => array_keys($request->input('form_state', [])), // ❌ Fails when form_state is string
]);

// After (handles both formats)
$isOldFormat = $request->has('form_state') && is_string($request->input('form_state'));

if ($isOldFormat) {
    // Handle old format (form_state as JSON string)
    $formState = json_decode($validated['form_state'], true);
    if (json_last_error() !== JSON_ERROR_NONE) {
        $formState = [];
    }
} else {
    // Handle new format (form_state as array)
    $formState = $validated['form_state'];
}

📊 Format Compatibility

The controller now supports both autosave formats:

Old Format (Current Frontend):

POST /subapplication/draft/save
Content-Type: multipart/form-data

form_state: '{"_token":"...", "fileno":"SUB-2025-...", "land_use":"Commercial", ...}'
progress_percent: 80
unit_file_no: "SUB-2025-14343359"
auto_save: "1"

New Format (Future):

POST /subapplication/draft/save
Content-Type: application/json

{
  "form_state": {
    "_token": "...",
    "fileno": "SUB-2025-...",
    "land_use": "Commercial",
    ...
  },
  "metadata": {
    "progress_percent": 80,
    "trigger": "auto",
    "last_completed_step": 1
  },
  "unit_file_no": "SUB-2025-14343359"
}
