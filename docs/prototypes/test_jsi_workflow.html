JSI (Joint Site Inspection) Workflow Testing Guide

🔄 Workflow Overview

The JSI system implements a 4-button workflow with proper state management:

1. Draft
→
2. Saved
→
3. Generated
→
4. Submitted

🔘 Button State Matrix

Workflow State Status Indicator Cancel Save Generate Submit
Draft (Not saved) 🔘 Gray dot - "Draft" Enabled Disabled* Disabled Disabled
Valid Draft (Form valid) 🔘 Gray dot - "Draft" Enabled Enabled Disabled Disabled
Saved (Record exists) 🟡 Yellow dot - "Saved" Enabled Enabled Enabled Disabled
Generated (Report created) 🔵 Blue dot - "Report Generated" Enabled Enabled Enabled Enabled
Submitted (Final) 🟢 Green dot - "Submitted" Enabled Disabled Disabled Disabled

* Save button enabled only when required fields are filled

📋 Testing Scenarios

Scenario 1: New JSI Report

  1. Open JSI modal for any application
  2. Expected: Status shows "Draft" with gray dot
  3. Expected: Only Cancel button enabled, others disabled
  4. Fill required fields (Date, Applicant Name, Location)
  5. Expected: Save button becomes enabled
  6. Click Save button
  7. Expected: Status changes to "Saved" with yellow dot
  8. Expected: Generate button becomes enabled

Scenario 2: Generate Report

  1. From saved state, click Generate button
  2. Expected: Button shows "Generating..." during process
  3. Expected: Status changes to "Report Generated" with blue dot
  4. Expected: Submit button becomes enabled
  5. Expected: Report opens in new tab (if URL provided)

Scenario 3: Final Submission

  1. From generated state, click Submit button
  2. Expected: Confirmation dialog appears
  3. Confirm submission
  4. Expected: Button shows "Submitting..." during process
  5. Expected: Status changes to "Submitted" with green dot
  6. Expected: All action buttons become disabled except Cancel
  7. Expected: Modal closes and page refreshes

Scenario 4: Existing Report Loading

  1. Open JSI modal for application with existing report
  2. Expected: Form fields populate from database
  3. Expected: Status reflects correct workflow state
  4. Expected: Buttons enabled/disabled according to current state

✅ Validation Testing

Required Field Validation:

  • Inspection Date: Must be selected
  • Applicant Name: Must not be empty
  • Location: Must not be empty

Test Steps:

  1. Open modal with empty form
  2. Expected: Save button disabled
  3. Fill only Date field
  4. Expected: Save button still disabled
  5. Fill Date + Applicant Name
  6. Expected: Save button still disabled
  7. Fill all required fields
  8. Expected: Save button becomes enabled
  9. Clear any required field
  10. Expected: Save button becomes disabled again

⚠️ Error Scenarios

Backend Integration Issues:

  • Save without backend route: Should show appropriate error message
  • Generate without saved record: Should prevent action and show error
  • Submit without generated report: Should prevent action and show error
  • Network failures: Should reset button states and show error

Data Integrity Issues:

  • Missing database columns: Should handle gracefully
  • Malformed JSON data: Should not break form population
  • Concurrent edits: Should handle conflicts appropriately

🛠️ Database Verification

Check Required Columns:

SELECT COLUMN_NAME, DATA_TYPE, IS_NULLABLE, COLUMN_DEFAULT
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME = 'joint_site_inspection_reports'
AND COLUMN_NAME IN ('is_generated', 'is_submitted');

Expected Results:

  • is_generated: BIT, NOT NULL, DEFAULT 0
  • is_submitted: BIT, NOT NULL, DEFAULT 0

Test Data Queries:

-- Check workflow states
SELECT id, application_id, is_generated, is_submitted, created_at
FROM joint_site_inspection_reports
ORDER BY created_at DESC;
