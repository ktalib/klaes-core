🔍 Test Scenarios

Test 1 PuA Commission - Buyer Card Visibility

Steps:
  1. Navigate to /commission-new-st
  2. Click the PuA tab
  3. Observe the page state (buyer card should be hidden)
  4. Select a PRIMARY file number from the dropdown
  5. Wait for parent details to load
✅ Expected Result:
  • Buyer selection card appears after parent selection
  • Card shows "Select Existing Buyer" heading
  • Dropdown is populated with buyers (or shows "No buyers available")

Test 2 Buyer Dropdown Population

Steps:
  1. With parent file number selected (from Test 1)
  2. Click on the buyer dropdown
  3. Review the options
✅ Expected Result:
  • First option: "-- No buyer selected (Manual entry) --"
  • Buyer options show: Name (Unit: XXX)
  • Only buyers NOT already linked to PuA file numbers appear
⚠️ Debug: Open browser console and check for API response from /api/st-file-numbers/buyers/{parentFileNumber}

Test 3 Buyer Selection Auto-Fill

Steps:
  1. Select a buyer from the dropdown
  2. Observe the buyer preview card
  3. Scroll down to applicant information section
  4. Check title, first name, and surname fields
✅ Expected Result:
  • Buyer preview card becomes visible
  • Shows buyer name, unit no, land use, unit size
  • Applicant fields are auto-filled with buyer data
  • Title dropdown matches buyer's title

Test 4 Commission PuA WITH Buyer

Steps:
  1. With buyer selected (from Test 3)
  2. Click "Generate PuA File Number" button
  3. Wait for success message
  4. Check browser network tab for request payload
  5. Query database: SELECT TOP 1 * FROM st_file_numbers WHERE file_no_type = 'PUA' ORDER BY id DESC
✅ Expected Result:
  • Success message appears with file number
  • Request payload includes buyer_list_id
  • Database record has buyer_list_id populated (not null)
  • File number format: ST-XXX-YYYY-N-001
⚠️ Important: Note the generated file number and buyer_list_id for later tests.

Test 5 Commission PuA WITHOUT Buyer (Manual Entry)

Steps:
  1. Refresh the page or reset form
  2. Select a different PRIMARY file number
  3. Leave buyer dropdown at "-- No buyer selected --"
  4. Manually fill in applicant information
  5. Click "Generate PuA File Number"
  6. Check database record
✅ Expected Result:
  • Commission succeeds without errors
  • Database record has buyer_list_id = NULL
  • Applicant data saved from manual entry

Test 6 Buyer Exclusion Logic

Steps:
  1. Commission a PuA with buyer_list_id = X (from Test 4)
  2. Refresh page
  3. Select the SAME parent file number again
  4. Open buyer dropdown
✅ Expected Result:
  • The buyer used in Test 4 should NOT appear in dropdown
  • Only unused buyers appear
  • If all buyers used, shows "No buyers available"

Test 7 Sub-Application Form - Buyer Card Removed

Steps:
  1. Navigate to any sub-application form
  2. Scroll through Step 1 form fields
  3. Look for "Select Existing Buyer" card
✅ Expected Result:

🐛 Troubleshooting

❌ Buyer Card Doesn't Appear

Possible Causes:
  • Parent file number not selected
  • JavaScript error preventing execution
  • API endpoint not returning data
Debug Steps:
  1. Open browser console (F12)
  2. Check for JavaScript errors
  3. Look for network request to /api/st-file-numbers/buyers/{parent}
  4. Verify API response is successful

❌ buyer_list_id Not Saving

Possible Causes:
  • Migration not run
  • Column doesn't exist in database
  • Validation error
Debug Steps:
  1. Run: SELECT TOP 1 buyer_list_id FROM st_file_numbers
  2. Check Laravel logs: storage/logs/laravel.log
  3. Review network request payload in browser DevTools

❌ Page Won't Load After Changes

Immediate Actions:
  1. Clear caches: php artisan config:clear && php artisan cache:clear && php artisan view:clear
  2. Check Blade syntax errors in modified files
  3. Review Apache/Nginx error logs
  4. Check file permissions
