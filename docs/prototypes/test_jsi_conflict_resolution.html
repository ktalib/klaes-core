✅ JSI Modal Conflict Resolution - Fixed!

Issue Resolution: JavaScript function conflicts causing data to disappear

Date: October 8, 2025

🎯 Problem Identified & Resolved

✅ Root Cause Found: Function name conflict between two JavaScript files
Conflicting Files:
  • programmes/partials/joint_site_inspection_js.blade.php - Primary applications
  • sub_actions/parts/sub_recomm_js.blade.php - Sub-applications
Symptoms:
  • JSI modal data loads then immediately disappears
  • Console log: {"applicationId": "2", "subApplicationId": "2064"}
  • AJAX error trying to fetch data that's already available

🔧 Solution Implemented

1. Function Renamed to Avoid Conflict:
// OLD (conflicting): function openJointInspectionModal() // NEW (unique): function openSubApplicationJointInspectionModal()
2. Added Conflict Override:
// Override any conflicting openJointInspectionModal function window.openJointInspectionModal = function(applicationId, subApplicationId) { // For sub-applications, use our specific function if (subApplicationId || window.location.pathname.includes('/sub-actions/')) { openSubApplicationJointInspectionModal(); } else { console.warn('Primary application JSI modal not handled in sub-actions context'); } };
3. Updated Function Calls:

All internal calls updated to use the new function name

⚡ Technical Details

Conflict Source:

The programmes/partials/joint_site_inspection_js.blade.php file was being loaded globally and had its own openJointInspectionModal function that expected different parameters and made AJAX calls.

Resolution Strategy:

Instead of trying to prevent the other file from loading, we:

  1. Renamed our function to be unique
  2. Added an override that routes calls appropriately
  3. Maintained backward compatibility
