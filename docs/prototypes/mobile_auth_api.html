Mobile User Authentication API

This document covers the dedicated login and logout endpoints that power the React Native mobile client. The routes live under /api/mobile, use Laravel Sanctum tokens, and rely on the existing users table (id, first_name, last_name, username, email, phone_number, password, is_active, etc.).

Quick Start

  1. Send a POST request to /api/mobile/auth/login with the user's identifier (username, email, or phone) and password.
  2. Store the returned bearer token securely on the device.
  3. Attach Authorization: Bearer <token> to any authenticated requests, including logout.
  4. POST to /api/mobile/auth/logout to revoke the current device token.

Endpoints

Method & Path Description Auth
POST /api/mobile/auth/login Authenticates with identifier + password. Accepts username, email, or phone and returns a Sanctum bearer token plus light-weight user info. Public
POST /api/mobile/auth/logout Revokes the bearer token that was used for the request (device-aware). Authorization: Bearer <token>

Login Request & Response

Request Body

{
  "identifier": "demo.user",        // username, phone, or email
  "password": "secret123!",
  "device_name": "ios-prod-device"  // optional, defaults to "react-mobile-app"
}

Successful Response

{
  "status": "success",
  "token_type": "Bearer",
  "token": "1|q3L5...",
  "expires_in_minutes": null,       // null = token does not auto-expire (Sanctum default)
  "user": {
    "id": 7,
    "first_name": "Demo",
    "last_name": "User",
    "username": "demo.user",
    "email": "demo@example.com",
    "phone_number": "+2348000000000",
    "profile": "https://cdn.example.com/avatars/7.png"
  }
}

Error Responses

  • 401 — Invalid credentials (wrong identifier/password).
  • 423 — Account exists but is_active = 0.
  • 429 — Too many attempts (handled by the global throttle:api middleware).

Logout Request

Send a POST with the same bearer token you wish to revoke.

POST /api/mobile/auth/logout
Authorization: Bearer 1|q3L5...
    
{
  "status": "success",
  "message": "Logged out successfully."
}

React Native Usage Example (fetch)

const login = async (identifier, password) => {
  const res = await fetch(`${API_URL}/mobile/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ identifier, password, device_name: 'ios-prod-device' })
  });
  if (!res.ok) throw new Error('Login failed');
  return res.json();
};

const logout = token => fetch(`${API_URL}/mobile/auth/logout`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}` }
});

Server Details

  • Routes: routes/mobile/auth.php loaded under the /api/mobile prefix.
  • Controller: App\Http\Controllers\Api\Mobile\MobileAuthController.
  • Guard: Laravel Sanctum (auth:sanctum) backed by personal_access_tokens.
  • User Model: App\Models\User now includes the HasApiTokens trait.

Keep tokens short-lived on the device, encrypt them if possible, and always send requests over HTTPS.
